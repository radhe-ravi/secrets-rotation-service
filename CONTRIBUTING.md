# Contributing Guidelines

Thank you for your interest in contributing!

## Branching Strategy

- main: production-ready code
- develop: integration branch
- feature/<name>: new features or fixes

## Pull Request Rules

- One feature per PR
- Unit tests required for all features
- No secrets or credentials allowed in commits
- Follow project coding standards (PEP8)

## Commit Message Format

<type>(scope): short description

Examples:

- feat(cache): add redis connector
- fix(audit): correct schema typo
